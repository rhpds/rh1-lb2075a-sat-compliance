== Run an OpenSCAP scan on a host

Now we will run an OpenSCAP scan on both `rhel1.lab` and `rhel2.lab`.

=====
Do the following to run an OpenSCAP scan on both `rhel1.lab` and `rhel2.lab`.

.Step 1 - Run an OpenSCAP scan on a host
[%collapsible]
====
Navigate to ** Hosts > All Hosts** and click on `rhel1.lab`.

NOTE: Due to a https://redhat.atlassian.net/browse/SAT-51400[bug] in the Satellite UI, this step is broken. We'll need to work around the bug by switching to the legacy UI.

Click on the burger button in the right side corner of the UI.

.Click on the burger button
image::burger-button.png[]

Select `Legacy UI`

.Click legacy UI
image::legacy-ui.png[]

Select both `rhel1` and `rhel2`.

.Select hosts
image::legacy-select-hosts.png[]

Click the `Select Action` button.

.Select action
image::click-select-action.png[]

Click `Schedule Remote Job`.

.Schedule Remote Job
image::schedule-remote-job.png[]

In the `Category and Template` menu do the following.

. Select the `OpenSCAP` job category.
. Select the `Run OpenSCAP scans` job template.

.Category and Template
image::category-and-template.png[]

Click next.

Then finally, click `Run on selected hosts`.

.Run
image::run-openscap-scan-multiple-hosts.png[]

====
=====

=====
Let's check the status of the job.

.Step 2 - Check the status of the job
[%collapsible]
====

To check the status of the ansible job, click on **Monitor > Jobs**.

.Jobs menu
image::monitor-jobs.png[]

Click on `Run scan for all openscap policies on host`.

.Run ansible roles
image::run-scan-openscap2.png[]

Click on rhe accordion button next to `rhel1` and `rhel2` to view the details of the job.

.Job details
image::run-scan-openscap-status2.png[]

====
=====

=====
We can now view the compliance report for both `rhel1.lab` and `rhel2.lab`.

.Step 3 - View the compliance report
[%collapsible]
====

To view the compliance report, click on **Hosts > Compliance > Reports**.

.Compliance reports
image::menu-compliance-reports.png[]

Click on the `Reported At` field.

.Reported At field
image::compliance-report.png[]

You'll see the compliance report for the host.

.Compliance report
image::compliance-report-rhel1.png[]

The tailoring file used to customize the OpenSCAP scan specifies that the host should not permit empty passwords. This report shows that the host has a compliance issue with this rule. As well, you can see that the scan only looks at this one rule. If we did not apply a tailoring file, the scan would look at all the rules in the benchmark.

====
=====

=====
We'll remediate the compliance issue on `rhel1.lab`.

.Step 4 - Remediate the compliance issues
[%collapsible]
====


To remediate the compliance issues, in the `Actions` column, click on the accordion button next to the `Hosts failing this rule` button and select `Remediation`.

.Remediate
image::remediate-compliance.png[]

In the `Disable SSH Access vis Empty Passwords` form, do the following:

. Check that `Remote job` is selected.
. In the `Snippet` drop down, select `Ansible`.
. Click next.

.Disable SSH Access vis Empty Passwords
image::disable-ssh-select-snippet.png[]

Click through to the `Review remediation` menu, review the changes and click on the `Run` button.

.Review remediation
image::review-remediation.png[]

On the next menu, click on the `Job details` button.

.Job details
image::job-details.png[]

You can review the details of the job and the output of the job.

.Job details
image::remediation-details.png[]

The lab is now complete.

Optionally, you can run another OpenSCAP scan to verify that the compliance issues have been remediated.
====
